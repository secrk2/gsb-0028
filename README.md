# 织云系统 · 应用台账与资产控制台

面向多团队的应用资产管理系统：**应用台账**（全生命周期登记）+ **资产控制台**（分布、变更、风险红点）+ **配置档案**（按应用×环境管理配置项、密文管控、环境对比、版本回滚、乐观锁）+ **变更留痕**（配置逐键流水 + 权限/交接流水、时间窗查询、差异清单导出）。

## 一键启动

```bash
docker compose up -d --build
```

访问 http://localhost:8016 。首次启动自动建库并写入初始数据（4 条业务线、10 个账号、24 个应用，覆盖 在研/上线/维保/下线 全部状态，含缺负责人 / 缺环境变量的红点样例，以及离职交接/权限调整留痕样例）。

本地开发（不用 Docker）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8016
```

## 权限与可见范围规则

- **四类角色**：平台管理员 / 业务线负责人 / 应用负责人 / 只读观察者。
- **两级收窄**：可见范围 = `业务线 × 环境`（`user_access` 一行授权一个组合）。比如陈晨只能看到「用户增长」业务线的「生产」环境，档案列表、台账、控制台、留痕、CSV 导出全部按此收窄；访问未授权的业务线/环境返回 **403 错误态页面并写明原因**（角色、目标范围、当前范围），不是空白页、也不是静默给空列表。
- **三项独立权限位，分开授予、分开校验**：
  - `can_view_secret` **密文查看权**：才能调 reveal 看明文（仍需填 ≥5 字理由、逐条留痕）；
  - `can_edit_config` **配置编辑权**：才能保存/回滚配置；
  - `can_manage_app` **应用管理权**：才能改台账信息、流转状态、改环境变量、发起交接、新建应用。

  **能看明文 ≠ 能改，能改 ≠ 能看明文**；只读观察者硬性禁止持有任何编辑/管理位（服务端强制，前端仅辅助）。
- 所有拒绝都带具体原因，例如「缺少『支付结算 · 生产』的配置编辑权：你在该范围当前为只读……」。

## 并发冲突（两个浏览器同时改同一条配置）

- 配置按「应用+环境」整体保存，每次成功保存生成一个新版本；编辑表单带着打开时的 `base_version`。
- 保存/回滚时服务端比对当前最新版本：**版本不一致直接 409**，返回对方在你之后保存的版本号、操作人、备注以及 `base→current` 的逐键差异（密文脱敏）。
- 前端弹出冲突框，二选一：**放弃改动、刷新后重新编辑**，或**确认风险后显式覆盖**；覆盖会生成新版本，并在版本备注与逐键留痕中写明「冲突后显式覆盖（基于 vX，覆盖 vY）」。**不允许后来者静默盖掉前一个改动。**

## 离职 / 转岗交接（留痕）

- 应用详情页「应用交接」：选择同业务线新负责人（只读观察者不可承接、不可跨业务线）、填 ≥5 字原因、选择是否收回原负责人在该业务线的全部权限。
- 交接的是**应用归属与权限**：配置项挂在应用上，配置档案 / 版本历史 / 逐键留痕随应用一并移交、归属不变、无需搬运；新负责人获得原负责人在该业务线各环境权限的并集，应用所属环境保证有应用管理权。
- **交接前后谁负责、权限如何处置、原因、生效时间**全部写入 `handover_records`（应用详情页可见）与权限流水；应用变更记录同步追加一条。
- **离职停用**：名下仍有应用时停用被 **409 拒绝并列明未交接清单**；交接清零后平台管理员才可停用，停用即收回全部授权，旧令牌立即失效。

## 其他既有规则

- **应用台账**：业务线 + 负责人 + 环境 + 状态 + 关键字组合筛选；状态机 `在研 → 上线 → 维保 → 下线`，只能向前，**下线终态只读**；同业务线应用名唯一（409 + 原因）。
- **密文管控（服务端强制）**：密文在档案、环境对比、版本快照、留痕、CSV 中一律脱敏（`••••••••`）；reveal 理由 ≥5 字、服务端校验、逐条留痕。
- **环境对比**：两个环境一键 diff（值不同/仅左/仅右/一致），只能选自己可见的环境；密文差异只提示不同。
- **版本与回滚**：回滚 = 追加新版本，历史版本与留痕原样保留、绝不覆盖；回滚同样带乐观锁。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 登录 |
| GET | `/api/me` · `/api/my/permissions` | 当前会话 / 当前角色与业务线×环境授权明细 |
| GET | `/api/apps` | 台账列表（按可见范围收窄；显式越权 403） |
| POST | `/api/apps` | 新建应用（需目标 BL×环境应用管理权） |
| GET/PATCH | `/api/apps/{id}` | 详情（含本人权限位）/ 修改（需应用管理权） |
| POST | `/api/apps/{id}/status` · PUT `/api/apps/{id}/env-vars` | 状态流转 / 环境变量（需应用管理权） |
| GET | `/api/console/summary` | 控制台汇总（按范围收窄） |
| GET | `/api/config/profiles` | 档案列表（BL×环境收窄） |
| GET | `/api/apps/{id}/config?environment=` | 某环境配置项 + 版本 + `current_version` + 权限位 |
| PUT | `/api/apps/{id}/config?environment=` | 保存（需编辑权；带 `base_version`，冲突 409；`force=true` 显式覆盖并留痕） |
| POST | `/api/apps/{id}/config/reveal` | 看明文（需密文查看权 + ≥5 字理由 + 留痕） |
| GET | `/api/apps/{id}/config/diff` | 环境对比（两环境均须可见） |
| GET | `/api/apps/{id}/config/versions[/{n}]` · `rollback-preview` | 版本与回滚预览 |
| POST | `/api/apps/{id}/config/rollback` | 回滚（需编辑权；同样乐观锁，追加新版本） |
| GET | `/api/config/audit` · `/api/config/audit/export.csv` | 配置留痕查询 / CSV 导出（范围收窄、密文脱敏） |
| GET/POST | `/api/apps/{id}/handovers` · `/api/apps/{id}/handover` | 交接记录 / 发起交接（归属+权限并集移交、留痕） |
| GET/PUT | `/api/users/{id}/permissions` | 查看/调整角色与授权（平台管理员或所辖业务线负责人；理由 ≥5 字；进权限流水） |
| POST | `/api/users/{id}/deactivate` | 离职停用（管理员；有未交接应用 → 409） |
| GET | `/api/permission-logs` | 权限变更流水（角色/授权/收回/停用/交接） |

认证：请求头 `X-Token: <登录返回的 token>`。所有错误返回 JSON `{"detail": ...}`；409 乐观锁冲突的 `detail` 为结构化对象（含 `code/base_version/current_version/intervening_versions/entries`）。

## 目录结构

```
app/
  main.py            # FastAPI 入口：台账/控制台路由（全部接权限与范围过滤）
  auth.py            # 四类角色、BL×环境 可见范围与三权限位判定、403 原因文案、列表过滤片段
  config_service.py  # 类型校验/快照版本/diff/回滚/审计查询/CSV + 乐观锁与冲突详情
  routers/config.py  # 配置档案 & 配置留痕 API
  routers/access.py  # 我的权限、人员授权、应用交接、离职停用、权限流水 API
  db.py              # 表结构（users/user_access/handover_records/permission_logs）+ 老库自动迁移
  seed.py            # 初始数据（四类角色、差异化授权、离职交接/权限调整样例）
  static/            # 前端（原生 JS，无构建步骤）
docker-compose.yml
Dockerfile
```
